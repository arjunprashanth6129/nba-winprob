            The network

            Architecture

            Each layer takes a weighted sum of the previous layer's outputs and passes it through SiLU, a smooth non-linear function. The last layer squashes a single number into a probability with a sigmoid. Stacking non-linear layers lets the network learn interactions, like possession mattering more when the game is close and late.

            Predictive ability

            Held-out test season

            lower log loss and Brier are better

            Log loss heavily punishes confident wrong calls. Brier is the mean squared error of the probability. AUC is how well it ranks winners above losers. Accuracy counts how often the favourite won, at every play of every game.

            Error through the game

            log loss by minute

            Pre-game Elo can't react to the score, so its error stays flat. The network's error falls steadily as the outcome becomes clearer. The network and logistic regression lines almost overlap: their gap is in crunch time (below). Error jumps in overtime, which restarts as a near coin flip.

            Limits

            • No player information. Injuries, rest days and who is on the floor aren't modelled. A star sitting out shows up only once it changes the score.
            • Team strength is Elo only. Ratings learn from results alone, so they're slow to react to trades and early-season changes. Betting lines would sharpen pre-game estimates.
            • The network ties logistic regression overall. The engineered inputs (lead ÷ √time) already make most game states nearly linear. Its edge is in close, late-game situations.
            • Missing data. About 260 games from 2019-20 have no play-by-play in the NBA's feed and are skipped.
            • Updates every 5 seconds. On the hosted site updates arrive by polling. Running locally uses a WebSocket that pushes each play as it's scored.
